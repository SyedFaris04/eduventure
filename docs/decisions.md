# Architecture decisions

Short records of choices that are expensive to reverse. Newest at the bottom.

## 1. Shared world, server-checked learning (2026-11-16)
React for screens, Phaser 3 for the world, Supabase for all data. Rewards are computed by database functions; the browser can only request them. No separate game server. Upgrade path if verified movement ever matters: add a Colyseus server.

## 2. Guest play (2026-11-16)
"Start Your Adventure" uses Supabase anonymous sign-in. Progress is saved server-side; guests can upgrade to an email account. Guests are excluded from chat, leaderboards and friends.

## 3. Three age bands from birth year (2026-11-16)
`under13`, `teen`, `adult` (plus `unknown` for guests who have not given a year). Age is the youngest possible for the year (`currentYear - birthYear - 1`), so protections lean safe. Under-13 accounts use a guardian's email, generated names and preset-phrase chat. Enforced in the database, not only the UI.

## 4. Answer keys never reach the browser before answering (2026-11-16)
Answers live in a table clients cannot read; a database function marks an answer and returns the explanation.

## 5. Questions are web UI, not canvas (2026-11-16)
Battle questions render as React over the Phaser canvas so screen readers, translation and right-to-left layouts work.

## 6. One character renderer (2026-11-16)
`renderCharacterSvg` produces layered SVG used by the creator preview and, rasterised, by the game world.

## 7. Grid logic, isometric drawing, Tiled maps (2026-11-16)
Movement and collision on a plain grid; isometric projection only for drawing. Maps are Tiled JSON so new regions reuse one system.

## 8. Tables and dependencies arrive with the phase that needs them (2026-11-16)
Each phase adds its own migration. GSAP dropped: CSS and `motion` cover the animations. Zustand bridges React and Phaser.

## 9. Seven interface languages from Phase 1 (2026-11-16)
en, ms, es, ar, zh, fr, ja via i18next. English is the source; others are marked unreviewed until a native speaker checks them. Questions stay in their original language.

## 11. Age band is computed, never stored (2026-11-16)
`profiles` keeps `birth_year`; every rule calls `age_band_for(birth_year)`. A stored band would keep a 12-year-old marked under-13 forever. Birth year can be set once (sign-up metadata or `set_birth_year`); later changes go through support.

## 12. Reference-data changes ship as migrations (2026-11-16)
The Supabase CLI does not re-run an already-applied seed, and raw SQL on production needs the owner's consent. `seed.sql` (generated by `npm run gen:seed`) builds fresh environments; fixes to live reference data are new migration files.

## 13. One progress guard decides where a player belongs (2026-11-16)
`guardRedirect()` in `src/app/progress.ts` wraps every setup page: signed out → welcome, no learning profile → onboarding, no hero → character creator. The loading screen prefetches this state so returning players land on Home directly.

## 14. Guest play needs CAPTCHA before public launch (2026-11-16)
Anonymous sign-in is rate-limited per IP by Supabase but otherwise open. Before any public launch, enable Supabase CAPTCHA (hCaptcha or Turnstile) for sign-ups and guest starts.

## 15. Draft questions only in the development project (2026-11-16)
`app_settings.allow_draft_questions` is true in this development project so battles can use questions still in review (shown with a Draft badge). **A production project must set it to false** (Phase 8 launch checklist). Answer keys live in `question_keys`, which clients can never read.

## 16. Phaser 3.90, not Phaser 4 (2026-11-16)
The brief specifies Phaser 3; 3.90 is its mature final release. Phaser 4 is the upgrade path; game logic is kept in plain TypeScript (`src/game/*.ts`) so only the scenes would change.

## 17. World logic is plain TypeScript; Phaser only draws (2026-11-16)
Projection, map parsing, movement, collision, pathfinding and the level curve are pure functions with unit tests. React overlays (HUD, dialogue, battle) talk to Phaser through one Zustand store (`src/game/store.ts`).

## 18. Battles start only from Interact, not by bumping into monsters (2026-11-16)
Avoids accidental battles for young players. The canvas renders at device pixel ratio (max 2) and pauses while the battle panel is open, to keep ordinary phones responsive.

## 19. Question files are the only authoring path until Phase 9 (2026-11-16)
`content/questions/*.json` is the single source of question content: validated by tests, imported by generated migrations. Reviewers only change status in `/admin`; a fix is a file edit with a version bump, which sends the question back to review. The in-app question editor moves to Phase 9 (educator tools), and `sync:questions` (exporting review status back to the files) moves to Phase 8, where it must come with a guard so a file can never mark a question published without a review record. Image questions (Supabase Storage) move to Phase 8 with the asset pipeline.

## 20. Test runs share Supabase's guest sign-in limit (2026-11-16)
The access-rule tests and the end-to-end tests both create anonymous users, and Supabase rate-limits anonymous sign-ins per IP per hour. Running both suites back to back can make the second fail with the app's "Too many tries" message; wait for the limit to reset (or raise it under Authentication → Rate Limits in the dev project only).

## 21. The world is drawn in 3D with React Three Fiber and KayKit art (2026-11-16)
The owner asked for a Clash of Clans / Clash Royale feel: real 3D, chunky chibi shapes, clear animation. The Phaser 2D world is replaced by a React Three Fiber scene (three.js was already installed for the landing page). The game logic moved unchanged into `src/game/sim.ts` (WorldSim), so movement, battles, rewards and every server rule stay the same. Art: CC0 KayKit packs (animation rig, trees, rocks, houses, well, fences) plus code-built hero parts and monsters in the same style. Free AI 3D generators were rejected as the main source: Meshy's free tier needs credit, Tripo's free tier appears to be non-commercial, and their models have no skeleton and drift in style. Babylon.js was rejected because it would add a second engine. Pre-rendered sprites were rejected because they aren't real 3D.

## 22. Still pictures are 3D snapshots (2026-11-16)
The HUD, Home, Shop, dialogue, battle panels and creator thumbnails show snapshots: one hidden WebGL renderer draws the same 3D hero or monster once and caches the picture. This keeps the Phase 1 rule that the creator, the menus and the world can never show a different hero. three.js loads only when a picture is first needed, so the first download stays small. Without WebGL, these pictures stay as empty boxes with the same labels.

## 10. Tailwind tokens are emitted statically (2026-11-16)
`@theme static` so every palette colour exists as a CSS variable for inline styles, SVG and canvas, not only when a utility class uses it.

## 23. A battle's island comes from the monster, never from the client (2026-11-17)
Each monster row has an `island_id`, and `public.islands` lists each island's subjects. `pick_question` reads the island through the monster: a client that pretends to be somewhere else gains nothing, because it can only name a monster, and the monster fixes the subjects. Island monsters fall back to the player's own subjects, then to any subject, so a battle starts whenever a Greenhaven battle would. Island bosses work the same way through `boss_island()`. Places are separate maps loaded one at a time, joined by a boat-ride scene (the user chose this over one big sea, which would be heavy on phones).

## 24. Level rewards come from one server list; the client keeps a checked copy (2026-11-17)
`public.level_unlocks` holds every level reward: helpers, island bosses, shop tiers, the boat and titles. Every gate is checked in a database function: `start_boss`, `buy_item`, `use_fifty`, `answer_question`, `answer_boss` and `set_title`. `src/game/unlocks.ts` is a copy used only for display (padlocks, "Level N", the "New unlock!" card). `tests/rls/unlocks.test.ts` fails if the two lists drift apart. Items bought before a gate existed stay owned and wearable; only new purchases are gated.

## 25. Lesson code runs in the browser; the server pays each lesson once (2026-11-17)
Python (Pyodide from jsDelivr, pinned to the same version as the test dependency) and JavaScript run in Web Workers on the learner's device. Each run has a 3-second limit (the worker is replaced to stop endless loops) and a 200-line output cap. The server marks only the steps it can check without running code: Predict (the chosen or typed output) and Fix (the corrected line, compared with spacing ignored by `norm_code`, the same rule as the app). Write steps are checked in the browser. `complete_lesson` requires every Predict and Fix step correct in the attempt and pays 25 XP and 10 gold once per lesson per player, so faking a lesson can never earn more than finishing it honestly. Running code on a server (needed later for Java) was deferred: it costs money and makes every Run wait on the network.

## 26. Lessons are reviewed content files whose samples the tests execute (2026-11-17)
`content/courses/*.json` holds the courses, validated by `lessonSchema.ts` and turned into migrations by `npm run gen:lessons`, like the question bank. The unit tests run every Learn sample, every Fix answer and every Write solution, plus every code-reading question in the bank: JavaScript in `node:vm`, Python in Pyodide. A lesson can therefore never state an output its code doesn't print. Lessons start "in review" and are published from `/admin`, where reviewers read them with their answers through RLS policies.

## 27. Language lessons share the lesson engine; every exercise is marked by the server, and listening is a bonus (2026-11-17)
The Language Hall uses the Code Academy's tables, functions, unit locking and review, with new step kinds: card, pick, match, build, gap, listen and type. Courses carry a `kind` ('code' or 'language'), and the Academy and Hall pages are the same pages filtered by it. With no code to run, the server marks every exercise. Typed answers are compared after `norm_answer` (case, spaces, final punctuation and quotes ignored, mirrored by `normAnswer` in the app). Match lists and build tiles are shuffled with a fixed seed so the public data never shows the answer order. Speech uses the browser's built-in voices (English, then Malay, then Indonesian as a close fallback). `complete_lesson` does not require listening steps, so a phone without a voice can still finish every lesson.

## 28. The pet grows from learning; gold is only a token fee, and gold is never sold (2026-11-17)
The knowledge pet's evolution gates are pet points (earned only from right answers, new lessons and days played) and the player level from `level_unlocks`. Gold is a small fee for the "Upacara Evolusi", not the gate: if gold could ever be bought, a gold gate would let money buy around learning, the pattern regulators and critics singled out in Prodigy. EDUVENTURE therefore keeps gold earn-only. The pet never decays, sickens or loses progress (guilt mechanics for children are named dark patterns), answer points are capped at 30 a day so farming stops paying, and names are a preset list. `pet_form` and `pet_next` are pure SQL functions mirrored in `src/features/pet/petRules.ts`, and `tests/rls/pet.test.ts` checks both sides agree. A finished lesson now records a learning day, so lessons count for the streak as well as answers.

## 29. Topics come back on a memory timer, never with a penalty (2026-11-17)
Each topic a player meets gets a timer in `topic_mastery` (`strength_days`, `due_at`), set by the pure `next_review()`: a right answer when the topic is due (or the first time) doubles its strength, up to 60 days; a right answer before it is due changes nothing, so cramming doesn't stretch the timer; a wrong answer resets it to one day and makes the topic due again in two minutes, after the player has read the "Why not?" card. Due topics with a question the player can be asked come back as up to three Returning monsters per island (`my_returning()`); a Returning battle (`start_encounter(monster, true)`) asks them first and pays +20 XP / +10 gold when won. The daily "Defeat N Returning monsters" mission is given only while something is due, sized to it. Overdue topics never lose anything: the research flags decay and loss mechanics as harmful for children. The encounters column is `is_returning` because RETURNING is a reserved word in Postgres.

## 30. Streaks are worked out from the days played, with shields that are only earned (2026-11-17)
`streak_from_days()` is a pure function over the player's learning days: a missed past day uses its ISO week's rest day, then a shield (one earned per 7 days played, at most two held), and only otherwise restarts the streak; today is never counted as missed, and protected days keep the streak without adding to it. Nothing is stored, so shields can't drift or be gamed, and the rules are tested with any list of days. Shields are never sold, there is no loss message or animation, and a broken streak shows the days learned this month instead of a zero. Players choose a number or week dots (`user_settings.streak_view`); under-13 players default to the dots, because the research ties streak pressure to compulsive use in children.

## 31. Parents approve through a shared link on their own account; limits are enforced by the database (2026-11-18)
Players under 18 (`age_band_for` under13 or teen) request a code (`request_guardian_code`, 8 characters, 7 days) and share `/parent?code=…`, usually by WhatsApp. A parent approves with `approve_child` only from a signed-in, non-guest account whose birth year makes them 18 or older, after ticking a confirmation; one guardian per child, audited. We chose this over emailing parents because it needs no email service and children often don't know a parent's address; its limit is that a determined teen could create a second adult account, which the confirmation makes a deliberate lie rather than an accident. The parent page is outside the onboarding guard and never signs out a guest session. `note_play` counts at most one minute per 50 seconds; a trigger on `encounters`, `boss_runs` and `lesson_attempts` refuses new starts once a parent's daily limit is reached, while answers in progress still finish. Learning is never blocked while approval is pending; future social features and purchases will require approval. This is not legal advice: the consent text needs a lawyer's review before launch.

## 32. The camera is the player's choice, saved per device; the default is lower and closer (2026-11-18)
The fixed 52° camera aimed at the hero's feet made faces hard to see. The world camera now follows `useCamera` (tilt 25–70°, distance 9–32, field of view 25–50°, a quarter-turn heading), saved in localStorage because a phone and a PC want different views. Presets: Close-up (28°, 10), Balanced (38°, 15, default), Classic (52°, 22, the old view), Overhead (65°, 27), after Animal Crossing's angled default with an overhead option and the accessibility guidelines' call for adjustable views with a reset. `lookHeight()` raises the aim toward the chest as the camera lowers. `screenDirToGrid(d, yaw)` keeps stick-up walking away from the camera after a turn; taps already hit the ground mesh, so they work at any angle. Free drag-orbiting was left out because dragging means walking on phones. The settings panel pauses the world, so slider keys don't walk the hero.

## 33. Questions are picked near a target chance of success, using Elo ratings (2026-11-18)
Each question has a rating (seeded from its 1–5 difficulty as −1 to +1 logits) and each player a skill per subject (from 0). After every battle or boss answer an AFTER INSERT trigger on `question_attempts` moves both by `K·(result − p)`, with `K` shrinking as answers accumulate (1.8 for players, 1.0 for questions, `/(1 + 0.05·n)`); a repeat of a question answered right in the last day moves nothing. `pick_question` and `pick_boss_question` keep every earlier rule and add a weight `exp(−(p − target)²/(2·0.12²))`, so choices stay random but cluster near the target: 0.775 normal, 0.875 Returning, 0.625 bosses, +0.075 for under-13s outside bosses (Pelánek's Elo practice systems default to about 75%). Ratings are visible to their owner but written only by the trigger.

## 34. Curriculum tags live in the content files; TP is estimated from Bloom levels (2026-11-18)
Questions gain `curriculum: {system, subject, years}`, parsed once from their alignment text by `scripts/tag-curriculum.mjs` (years from "Tahun/Tingkatan/Form N–M", else from the level) and written into the content files so reviewers can correct them; `questionProblems` requires the tag whenever the alignment names KSSR or KSSM. `gen:questions` carries the tag and sets it on existing rows in a separate update, so tagging never bumps versions or sends questions back for review. TP comes from Bloom (remember 1, understand 2, apply 3, analyse 4, evaluate 5, create 6) as a generated column; `estimate_tp` gives the highest level with at least two right answers at or above it and 60% right there. The parent report labels it an estimate: official PBD levels are a teacher's judgement against DSKP descriptors, which need an educator to map.

## 35. Classes share a child's learning only after a parent approves (2026-11-18)
The owner decided that players under 18 join a class only once a parent has approved their account (`join_class` checks `guardianships`); adults join directly. Any adult email account can create a class: there is no teacher verification yet, so the parent gate is what protects children's data, and teachers see only character names and learning progress (never email or age). Removing a parent link takes the child out of every class (trigger on `guardianships`), and parents can remove a single class. Quest progress is counted live from `question_attempts` (right answers on the topic since the quest was set, at its TP or above), so nothing can drift; open quests weigh their topic ×4 in `pick_question`. Seeing classmates, raids and chat wait for the multiplayer phase.
## 36. Scenery in front of the hero is cut away in the shader (2026-11-18)
Props are drawn as instanced meshes shared across the map, so fading one tree is not possible without per-instance state. Instead `addSeeThrough()` patches every scenery material (after the wind patch, which it chains): fragments closer to the camera than the hero, inside a circle around the hero on screen, are discarded — fully in the middle, dithered over the outer third. The world updates the shared uniforms each frame (hero screen position, depth, a radius sized to the hero's height on screen). Shadows use separate depth materials, so cut trees still cast them. Characters, monsters, the ground and water are not patched.

## 37. Music and sound effects are composed in code; real tracks can replace them (2026-11-18)
One Web Audio context (`src/audio/engine.ts`) with master, music and effects buses. Music is generative: pentatonic bars (pad, sparse plucked lead, bass) scheduled a second ahead, one mood per island and a calm "study" mood elsewhere, crossfading over two seconds; a director follows the route, the island and open panels, playing at half volume in battles and lessons (the research warns that distractions hurt short learning moments) and lower while the Language Hall speaks. Effects are short envelopes; mistakes never use harsh waveforms. This needs no downloads or licences and works offline; files listed in `public/assets/audio/manifest.json` replace a mood's music when the owner has real tracks. Sound stays off until the player turns it on, because browsers only allow audio after a tap; volumes are saved per device.

## 38. The pet's guess is uniformly random, so teaching it is never a hint (2026-11-19)
The protégé effect is the pet research's strongest result, so the pet sometimes "attempts" a question: `pet_guess_pick` gives about one choice question in five a guess drawn uniformly from its options. A uniform guess carries no information about the answer, so it cannot become a 50/50 helper; the player answers as usual, and a right answer over a wrong guess pays +2 pet points inside the same 30-a-day cap as answers. Adventures start on every third first-time lesson since hatching or the last adventure, last six hours and wait indefinitely for the player: the pet still follows the hero meanwhile, so being "away" is a story, never an absence or a reason to worry.

## 39. The camera turns all the way round, without taking over walking controls (2026-11-20)
The camera heading is now any angle (`useCamera().yaw`, degrees; old quarter-turn saves migrate). Left click and single-finger taps still walk, so turning uses the right mouse button, Z / X (E stays the interact key), two-finger twists on touch screens (with slide-to-tilt and pinch-to-zoom), and a 0–359° slider in Settings. Continuous changes update the camera at once and save a moment later. `screenDirToGrid(d, yaw)` already keeps stick-up walking away from the camera at any heading.

## 40. Harvesting is one question per node; materials, tools and camps live in the database (2026-11-20)
The islands grew to about twice the area (`scripts/expand-maps.py`, run once; the maps stay hand-editable). New land in the north and east holds harvest nodes: trees (wood), rocks (stone), herb bushes (herbs) and crystal rocks (crystal, which needs a pickaxe). Harvesting asks one quick question picked like a battle question: right gives 2, wrong gives 1 with the "Why not?" card, plus +1 or +2 from a stone or crystal tool. Answers are recorded like battle answers (mastery, ratings, missions, streak) but pay no XP or gold, so harvesting can't become an XP farm. The server keeps the list of real nodes (`harvest_nodes`, generated from the maps by `scripts/gen-nodes.py`), a 3-minute regrowth per player and node, and one pending question per player; asking again for the same node returns the same question, so a reload or overlapping request never shows one question and marks another, and a hard question can't be re-rolled. Recipes craft four tools and seven cosmetics that are kept in `shop_items` with `craft_only` (so wearing them reuses the ownership checks) and are never sold. Each island has a shared camp with four projects (bench, lantern, flag, whiteboard stand) that everyone builds by giving materials; the whiteboard stand is where the whiteboard camps (multiplayer phase) will go.

## 41. Festivals run on dates in the database, pay their own tokens, and never pressure players (2026-11-20)
The year-end school holiday, Chinese New Year, Ramadan and Hari Raya (one festival, from the start of Ramadan to a week after Aidilfitri), Merdeka (to Hari Malaysia) and Deepavali each have a row in `festivals` with start and end dates in Malaysia time; the owner corrects moon-dependent dates in the Supabase table editor, and next year's festivals are new rows. One server function, `active_festivals(uid)`, says what is on, so missions and the stall can't be claimed or bought outside a festival. While a festival is on, the Kampung shows its decorations, five festival missions (one daily, four lasting the whole festival, including the new `harvest` and `lesson` kinds) pay festival tokens, and a stall in the shop sells that festival's hero item (30 tokens) and pet item (20 tokens). There are no countdowns or "last chance" wording, festival items return every year at the same price, and tokens never expire, so missing a festival costs nothing. Decorations follow the content rules: lanterns, mandarin oranges, pelita, ketupat, bunting in red, white, blue and yellow (never the flag), kolam and lights; no religious symbols. `claim_mission` now refuses any mission that is no longer current, which also closes stale daily claims through the API. Admins can preview any festival on their own account from `/admin`; "reset" removes their own festival missions and items for it and sets their tokens to 50, so the live tests can repeat on the production database.

## 42. Players see each other through a free Cloudflare room server; Supabase keeps every safety rule (2026-11-21)
Supabase Realtime bills each message once per receiver, so its free plan covers only about 17 hours of one full island a month; the owner chose Cloudflare's free plan instead (outgoing WebSocket messages are free). `server/rooms` is a Worker with one SQLite-backed Durable Object per island room, using the Hibernation API so idle rooms cost nothing. Rooms hold 12 visible players; a full room sends the next player to the next slot. The server holds no Supabase secret: a joining player's own token is used to read `my_room_card()`, so only a real sign-in gets in and nobody can fake another player's name or look. Other players get a random `public_id`, name, appearance and pet, never an account id, age, level or gold. Positions are display-only (2 a second while moving) and nothing of value depends on them. There is no typing in this phase: six emotes, which a parent's "chat off" switches off for under-13s. Under-13s (and unknown ages) are hidden from others until a parent approves the account (the owner's decision); players can hide themselves, parents can hide their child (a flag the child can't change), and moderators can ban from multiplayer. Typed names (13 and over) pass a server word filter (`content/blocked-words.txt`, English and Malay, with leetspeak folded); a name that later fails shows as "Player". Players can hide another player for themselves or report them; reports reach `/admin` for admins and moderators. Visibility changes apply when a player next joins a room; a player's own switch reconnects them at once. Multiplayer is off until `VITE_ROOMS_URL` is set, so the game works fully without the server.

## 43. Island camp boards: lasting notes, safe by age, all checked on the server (2026-11-21)
The owner asked for a whiteboard at each island's camp where players gather and write, and chose "safe by age" and a lasting board (notes stay for everyone who visits, not only the players there at that moment). Notes live in `board_notes`, reached only through server functions, so the board works without the room server and every note can be moderated; an open board refreshes every 20 seconds (no Supabase Realtime, to stay inside the free plan). A board opens once the island has built its whiteboard stand. A note is a sticker, a ready-made phrase (stored as a key and shown in each reader's language) and, for players 13 and over, up to 120 characters of text in Latin letters only (the owner's choice: the word filter knows English and Malay, so other scripts could slip past it). `text_ok` refuses other scripts (including letters it can't fold to a-z, such as ı or ū, which would split a word), phone numbers (7 digits with only non-letters between them), email addresses and links (also with spaces around the @ or the dot), @handles, contact words ("gmail dot com", messaging apps) and blocked words; sentences are checked word by word, because squashing a sentence like a name refuses ordinary text, and punctuation inside a word ("fu.ck") is removed first. Writing shows your name, so it follows the visibility rules (banned, hidden by a parent or yourself, or an under-13 waiting for a parent: read only); under-18s need an approving parent, who also gets a "Can write on camp boards" switch; adult guests only read (anyone can claim to be an adult as a guest), but a guest under 18 with an approving parent may write. Under-13 and unknown-age readers never receive typed notes. Limits: 5 notes an hour (deleted notes count), notes shown for 3 days (kept 30 for moderators, longer while a report is open; deleting your own note only hides it, so reports keep their evidence), 3 reports from different players hide a note until a moderator removes or keeps it in `/admin`. Writing earns nothing. A hidden `qa_camp` board, always built and reached by no map, serves the live and end-to-end tests, because the test database is production.

## 44. The Android app opens the game hosted on GitHub Pages; GitHub Actions builds both (2026-11-21)
The owner wants people to download the game as an Android app from a shared website, built in the cloud for free, and chose an app that loads the game live: every fix reaches all players at once, and old apps can't break when database functions change. The game is published to GitHub Pages at `/eduventure/play/` (no new account; the repository is public, so Actions minutes are free); the site root is a download page that the website project will replace, from the same repository and workflow, because a Pages deploy replaces the whole site. The owner chose GitHub's address over a custom domain, and every APK has it built in. Vite's `base` comes from `BASE_PATH` only in the Pages build, the router's `basename` follows it, and asset URLs and email or parent links go through `withBase`/`appUrl`; Pages has no fallback for deep links, so `play/404.html` is the game itself. The app is a Capacitor 8 shell (`capacitor.config.json`; a `.ts` config can't load with TypeScript 7) with `server.url` pointing at the game, a bundled offline page, the cat from the loading art as its icon and the logo as its splash. Android's back button closes the open panel but never a battle question, goes back a page, and leaves the app from the first pages; safe-area insets keep the HUD clear of notches and gesture bars. Every APK is signed with one release key kept in GitHub secrets (and backed up by the owner) so each installs over the last; `versionCode` is the Actions run number, and an APK is released only after the Pages deploy it opens has succeeded. A device pass screenshotted every main screen at phone, tablet and laptop sizes: the welcome page now goes side by side on phones held sideways, and home uses equal columns on tablets.

## 45. The website is a second Vite page in this repository that reuses the game's 3D (2026-11-21)
The owner wanted an interactive website with 3D and a download section, built in code and hosted free. It is `site/`, built by `vite.site.config.ts` at `/eduventure/` and published with the game (decision #44), so the download page, the game and the APK come from one workflow. It imports the game's 3D code (the floating island with a new optional `spin`, the Sproutling, the knowledge pet) instead of redrawing it, but not the game's i18next, Supabase or router: its English and Malay words live in `site/copy.ts`, and its demo battle uses three questions stored in the page (no server, no account). three.js is only in lazy chunks: each scene loads when it scrolls near the screen and stops drawing when off it, and devices without WebGL or that ask for less motion get still pictures (the loading art, and a slime and pet drawn in CSS). The welcome page's "4 cores or fewer" rule isn't used, because it would hide the 3D from many phones. The QR code for the APK is a committed SVG checked against the download link by a test. `check-pages` covers the site too: both buttons, the language switch, a demo answer, the QR code, and no sideways scrolling on a 320px phone in either language.

## 46. Phones play sideways, and the world fits a 360 px tall screen (2026-11-21)
The owner wanted the game always in landscape because phones sometimes needed scrolling. The Android app's activity is locked to `sensorLandscape`. In browsers a site can't force orientation, so "Tap to start" asks phones (a touch screen whose short side is under 600 px) for full screen and the landscape lock, which Chrome on Android grants, and a phone held upright anywhere else (iPhone Safari) sees a "Turn your phone sideways" screen; tablets and laptops are unchanged. Compact layouts use the `short` variant (landscape and max-height 500 px) only, so larger screens don't change: battle and boss fights put the monster and health bars in a left column and the question on the right; the boat lists islands in two columns; settings put the camera on the left and sound and graphics on the right; sign-in puts the form beside Back; home puts "Enter the World" first; the shop shows smaller cards three to a row. A panel never makes the page scroll; long content (a question's explanation, the camera sliders) scrolls inside its own area. In a battle or boss fight on a sideways phone, Run away and Continue sit in the left column (always on screen) and the Answer button stays pinned at the bottom of the question. The rotate screen covers the game only: the parent, teacher, admin, sign-in and password pages stay usable upright (a parent approves from a WhatsApp link). A phone is decided by the device's screen, not the window, so a tablet in split screen is never asked to rotate. Desktop windows shorter than 500 px also get the compact layouts, which is fine. `tests/e2e/landscape.spec.ts` checks every world panel and the main pages at 740 × 360, and that Answer and Continue stay on screen for the longest real multi-select, ordering and matching questions at 740 × 360 and 667 × 320 (Safari on a sideways iPhone); the device-shots tool takes `DEVICE_SIZES=landscape`.

## 47. Harvesting is three slashes, with no question (2026-11-21)
The owner wanted harvesting to feel like action: near a tree, rock, herb bush or crystal, the action button (or E, Space or Enter) swings the hero's attack, chips fly and a chop or clink plays; the third swing at the same node (within 3 seconds) asks the server for the materials and shows "+2 Wood" (more with a stone or crystal tool) or why not. `slash_harvest` keeps the old rules (a real node, not regrowing, a pickaxe for crystal, the daily play limit) and adds at most one finished harvest every 1.5 seconds per player, so a script cannot farm; the server cannot see where the player stands, so the regrowth and that pace are the limits. Harvests still count for the festival harvest missions but no longer as learning answers (battles and lessons teach). Because materials now come faster, recipes cost half as much again (rounded up) and unfinished camp builds twice as much. The question window is gone; `start_harvest`/`answer_harvest` remain for older clients.

## 48. My island: a private island each, built from harvested materials (2026-11-21)
The owner wanted players to use what they harvest to build their own home and area, creatively, with a lot to choose from. "My island" is first on the boatman's list: a private 32 × 32 place (no monsters, harvest nodes, camp, festival decor or multiplayer room) with a 24 × 24 build area (x and y 4–27). Build mode (🔨) lists 50 items in 8 groups (houses, garden, trees, paths and fences, lights, furniture, Malaysian, water), each with a footprint, a blocking flag and a cost in wood, stone, herbs and crystal; 15 unlock by level through the shared `level_unlocks` list (kind `island_item`), so level-ups announce them. The catalogue's one source is `content/island-items.json`: `npm run gen:island` writes its seed migration and the client imports the same file. A tap places the chosen item centred on that tile (Turn rotates by 90°); Move picks an item up and puts it down; Remove refunds every material. The server decides everything (`place_island_item`, `move_island_item`, `remove_island_item`: inside the area, no overlap, level, materials, at most 400 items, one at a time per player, the daily play limit for placing and moving), and the client predicts with the same rules (`src/features/island/rules.ts`) so the ghost turns red before a refused tap. Items are drawn in batches by kind, block walking as soon as they are placed, and show as 3D thumbnails on the cards. Visiting other islands, interiors and signs with text are left for later.


## 49. Recorded CC0 music and effects, code sound as the fallback (2026-11-21)
The owner wanted cuter, more attractive sound and music and chose recorded, free-licence files over better code-made
sound. Each mood (plus a new `cozy` mood for My island) plays a recorded loop, and 13 effects use recorded clips; defeat,
splash, chirp and sparkle stay code-made (already gentle, and no recorded clip fitted). Only CC0 sources are used, so
there is no attribution duty or commercial limit; every file is still credited in `public/assets/audio/CREDITS.md`, and
a test checks the manifest, the files and the credits agree. Music is levelled to −16 LUFS, effects to a −6 dB peak.
Recorded music skips the echo the code music uses. Files missing from the manifest, still loading, or failing to load
fall back to the code sound, so nothing goes silent. The picks were made without listening (by licence, length and
measurement); the owner listens and swaps any file by name.
